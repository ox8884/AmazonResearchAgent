# 리서치 앱 실화면 점검 및 개선 방향

점검일: 2026-09-04
대상: https://amazon-research-agent.hyj5317.workers.dev/ko
방법: 사용자 로그인 후 Codex 인앱 브라우저에서 주요 화면을 직접 이동하고 화면 텍스트와 외관을 확인.

## 결론

주요 화면은 열리지만, 수집한 자료를 사용자의 구매 판단으로 연결하는 과정이 부족하다. 색상이나 장식 변경보다 **근거 상태 정합성 → 후보 상세의 판단 정보 → 실행 결과 추적 → 설정 설명** 순으로 개선한다.

이번 작업은 읽기 전용 점검이다. 코드·설정 변경, 리서치 실행, 연결 테스트, 유료 API 호출, 파일 업로드는 수행하지 않았다. 보안 감사나 전체 기능 테스트 통과를 의미하지 않는다.

## 확인 범위

- AI 설정: 저장된 provider 3개 표시, 선택된 Opencode-Go 폼 확인.
- 대시보드: 대표 후보와 후보 상세 링크, 파이프라인 표시 확인.
- 후보 목록 및 대표 후보 상세: 실제 링크 이동과 데이터 표시 확인.
- 실행: 최근 실행 10건 목록 확인.
- 가져오기 목록 및 새 가져오기: 이동과 빈 파일 선택 상태 확인.
- 일반 설정: 읽기 전용 설정 확인.
- 외관: 현재 인앱 브라우저 폭에서 AI 설정·후보 목록 스크린샷 육안 확인. 별도 모바일/데스크톱 폭별 검증은 미수행.

## 1. 우선 수정: 근거 없음 안내와 실제 자료가 불일치

### 관찰

대시보드와 후보 목록은 pancake dispenser bottle에 대해 ‘수집된 근거가 없어 아직 판단할 수 없습니다’를 표시한다. 그러나 같은 후보 상세에는 keyword metrics, historical search volume, sales estimates, share of voice 자료와 분석 항목이 보인다. 반면 판매가와 Amazon 수수료는 비어 있다.

### 수정 방향

- ‘자료가 전혀 없음’, ‘일부 자료 수집됨’, ‘필수 자료 부족’, ‘판단 가능’을 구분한다.
- 대시보드·목록·상세가 같은 근거 상태 계산을 사용하도록 관련 코드를 확인한다.
- 현재 사례에는 ‘수요·경쟁 자료 수집됨, 판매가·수수료 미확인’처럼 실제 부족 항목을 표시한다.
- 총점 50이라는 분석 필드와 핵심 신호의 ‘미계산’이 다른 의미인지 데이터 계약을 먼저 확인한다. 임의로 같은 점수로 연결하지 않는다.

### 완료 기준

자료 없음 / 일부 수집 / 필수 자료 충족 사례에서 세 화면의 설명이 일치한다. 근거 부족 상태를 GO로 승격하지 않는다.

## 2. 우선 수정: 후보 상세를 사람이 읽을 수 있는 검토 화면으로

### 관찰

본문에 analysis_verdict, economicsSource, candidateState 같은 내부 이름이 노출된다. 근거와 사유가 ‘2 items’, ‘structured data’로 축약되어 내용을 알 수 없다. 비율은 긴 소수로 표시된다. 정상 수집 자료도 ‘아직 부족한 근거’ 아래 섞여 있다.

### 수정 방향

1. 상단: 현재 판단, 판단 이유, 다음 필요한 확인.
2. 수요·경쟁: 검색량, 계절성, 브랜드 집중도와 출처·관측 기간.
3. 수익성: 판매가, 수수료, 공급가/DDP, 광고 가정, 예상 마진. 미확인은 미확인으로 유지.
4. 부족한 근거: 빠진 항목만 따로 표시.
5. 원본 자료: 내부 필드와 원본 데이터는 기술 세부 정보로 이동.

비율은 데이터 의미를 확인한 뒤 퍼센트와 적정 자릿수로 표시한다. 사유와 근거 항목은 펼쳐 실제 내용을 읽을 수 있어야 한다. 추정과 관측값을 명확히 구별한다.

### 완료 기준

사용자가 내부 필드명을 몰라도 ‘왜 보류인지, 어떤 자료가 있는지, 다음에 무엇을 확인할지’를 설명할 수 있다. 수치는 원본과 대응하고 누락값을 임의로 채우지 않는다.

## 3. 실행 결과와 진행 상태를 추적 가능하게

### 관찰

실행 목록에는 완료 여부·실행 방식·시각·긴 식별자가 표시되지만, 확인한 화면에는 실행 상세로 들어가는 링크가 없다. 대시보드에는 실행 중 작업 2개가 보인다. 실행 목록의 완료 상태와 작업 대기열은 단위가 다를 수 있으므로 이 사실만으로 정체나 오류라고 판단하지 않는다.

### 수정 방향

- 실행과 개별 작업의 관계를 먼저 확인한다.
- 실행별 처리 후보 수, 성공·실패·대기 수, 관련 후보 링크를 제공한다.
- 실행 중 작업에는 시작 시각과 마지막 갱신 시각을 제공한다.
- 식별자는 복사 가능한 보조 정보로 낮춘다.
- API 예산 7/20의 단위와 집계 기간을 명시한다.

### 완료 기준

사용자가 실행 한 건을 열어 결과 후보와 미완료 원인을 추적할 수 있다. 정상 진행과 멈춘 작업을 구분할 근거가 표시된다.

## 4. 실제 리서치와 앱 데이터의 연결 확인

### 관찰

현재 이 배포본에는 후보 1개와 가져오기 1건이 표시된다. 최근 대화에서 다룬 대나무 선반·공급업체 RFQ가 앱에 저장되어 있는지는 이 화면에서 확인되지 않았다.

### 다음 확인

현재 배포본·연결 데이터 저장소·수동 리서치 보고서의 관계를 확인한다. 다른 환경에 데이터가 있는지, 보고서에만 남아 있는지 먼저 구분한다. 확인 없이 DB를 바꾸거나 자료를 재생성하지 않는다. 이후 후보와 공급업체 견적을 연결하는 최소 저장·조회 흐름을 별도 범위로 정한다.

## 5. AI 설정과 일반 설정의 설명 개선

### 관찰

AI 설정에는 provider 3개 활성과 ‘0 주의 필요’가 표시된다. 이는 실제 연결 성공 여부를 이번 점검에서 확인했다는 뜻은 아니다. 역할명과 우선순위 설명이 기술적이며, 현재 폭에서는 설정 폼이 길어 주요 조작까지 스크롤이 필요하다. 일반 설정에는 API 예산이 있지만 총 상품 출시 예산은 보이지 않는다.

### 수정 방향

- 활성화 상태와 최근 연결 테스트 결과를 별도로 표시한다.
- 역할에 한국어 이름과 짧은 용도 설명을 붙인다.
- 우선순위의 실제 정렬 규칙을 코드에서 확인한 뒤 도움말을 제공한다.
- 선택한 provider 이름과 저장·테스트 상태를 쉽게 찾도록 배치한다.
- API 사용 예산과 상품 출시 예산을 혼동하지 않게 구분한다. 총 출시 예산 $3,000을 어디에서 적용하는지는 별도 확인한다.

## 권장 작업 순서와 범위

1. 근거 상태 계산과 문구 정합성을 먼저 수정한다.
2. 동일 데이터를 사용해 후보 상세의 표시 계층을 개선한다.
3. 실행 결과 추적과 예산 단위 설명을 보완한다.
4. 실제 조사 결과의 저장 위치를 확인하고 후보·RFQ 연결 범위를 정한다.
5. 마지막으로 화면 간 여백·표·타이포를 통일하고 여러 화면 폭에서 확인한다.

첫 구현은 1~2번으로 제한하는 것이 적절하다. 관련 코드·테스트를 직접 읽고 최소 변경 파일을 확정한 뒤 진행한다. 이번 보고서 자체는 구현 또는 배포 승인을 의미하지 않는다.

## 추가 요구: 프론트엔드 전면 재설계

사용자는 현재 프론트엔드의 전반적인 디자인에 만족하지 않으며, 부분적인 색상·여백 조정보다 화면 구성부터 다시 설계하기를 원한다. 이번 요청은 이 요구를 보고서에 반영하는 것이며, 실제 코드 변경은 아직 수행하지 않았다.

- 목표: 전문적인 리서치 도구에 어울리는 일관된 시각 체계와, 버튼의 역할·현재 상태·다음 행동이 바로 읽히는 화면.
- 범위: 공통 내비게이션, 대시보드, 후보 목록·상세, 실행, 가져오기, 일반 설정, AI 설정의 정보 구조와 화면 구성.
- 기존 디자인의 색상·레이아웃을 고정 전제로 삼지 않는다. 의미 없는 장식이나 큰 카드 반복 대신 실제 리서치·비교·판단 흐름을 중심으로 설계한다.
- 먼저 대시보드와 후보 상세의 대표 시안을 제시하고 방향을 확인한 뒤 공통 컴포넌트와 나머지 화면으로 확장한다. 정확한 근거 표시 개선은 재설계의 필수 조건이다.
- 보존: 인증, API 키, provider 설정, 기존 사용자 데이터, 비용·실행 통제. 시각 개편을 이유로 DB·API 계약을 임의 변경하지 않는다.
- 완료 기준: 대표 화면의 변경이 명확히 구별되고, 핵심 행동과 판단 근거를 쉽게 찾을 수 있어야 한다. 한국어 줄바꿈, 모바일·데스크톱, 키보드 접근, 상태별 표시를 검증한다.
- Evidence: 변경 전후를 같은 데이터·화면 폭·인증 상태로 촬영하고 서로 다른 파일로 보존한다. 비교 페이지와 검증 결과를 남기며, 확보하지 못한 BEFORE는 없다고 명시한다.

음성에 포함된 경로 표현은 정확히 식별되지 않았다. 실제 구현 전 대상 프로젝트와 실행 중인 배포본을 확인하며, 추정 경로를 기준으로 다른 프로젝트를 수정하지 않는다.

## 후속 검증 체크리스트

- 근거 상태별 실제 화면 비교와 관련 기존 테스트.
- 후보 목록 → 상세 → 뒤로 이동 및 현재 선택 상태 확인.
- 한국어/영어와 모바일/데스크톱 가로 넘침·키보드 접근 확인.
- 기존 API 키·provider 설정·사용자 데이터 보존.
- 변경 전후 화면을 서로 다른 경로로 보존. 이번 점검은 브라우저 도구 관찰 결과를 바탕으로 하며 별도 PNG 파일을 저장하지 않았다.
