# 앱 데이터와 수동 리서치 연결 점검

## 확인한 사실

- 2026-09-04 Codex 인앱 브라우저에서 Cloudflare 배포본 `/ko/dashboard`와 후보 상세를 열었다. 후보는 `pancake dispenser bottle`, ID `cccdb1c3-20eb-52ae-bd4f-5c8c0fd63454`다.
- 체크아웃의 연결 대상 Supabase에 읽기 전용 조회를 실행했다. 후보는 위 1개, 해당 근거 종류는 11개, 리서치 실행은 완료 10건이다. 배포 화면의 후보/근거 목록과 일치한다. Worker에 저장된 secret 값 자체는 조회·출력하지 않았다.
- 공개 스키마 테이블 이름에서 supplier/quote/rfq를 포함하는 테이블은 없었다. 후보 행에도 대나무 선반이 없으므로 최근 RFQ가 이 후보 목록에 연결되었다고 볼 수 없다. 다른 테이블의 모든 JSON 또는 별도 로컬 DB까지 전수 검색했다는 의미는 아니다.
- 공유 볼트 `Hermes/OMO/세션로그/2026-09-04.md`에는 Forge Kitchen 대나무 선반의 조사·공급업체 shortlist·승인된 연락 이력이 있다. 이는 문서 기록이며 이번 점검에서 이메일/Alibaba 발송 여부를 다시 검증한 것은 아니다.
- `review-logs/2026-09-04-budget-first-jungle-scout-rescan.md`에는 총 출시 예산 $3,000 및 재고 DDP $1,800 계획이 기록되어 있다. 현재 앱의 API 예산은 호출 건수 제한이며, 상품 출시비를 집행·차단하는 한도와 다르다. 제품 코드 검색에서도 출시 예산 $3,000의 자동 집행 기능은 확인되지 않았다.

## 실행 상태의 별도 발견

- `jobs`의 running 2건은 모두 `TEST_AI_PROVIDER_CONNECTION`이다. candidateId/researchRunId 연결은 없었다.
- 두 작업의 마지막 갱신은 2026-09-04 06:34~06:35 UTC, 임대 만료는 06:36~06:37 UTC다. 점검 시각보다 이전이다.
- 따라서 대시보드 전체 작업 수를 진행 중인 리서치 수로 해석하면 안 된다. 임대 만료는 갱신/소비자 확인이 필요하다는 증거이지, 임의 재실행·유료 연결 테스트의 승인이 아니다. 이번에는 작업 상태를 수정하거나 재시도하지 않았다.

## 최소 후속 연결 범위

1. 먼저 대나무 선반의 기준 레코드와 근거 출처를 확정한다. 기존 pancake 후보 ID에 다른 상품의 견적을 붙이지 않는다.
2. 제품 사양(2-pack 등), 수량, 공급가, DDP 포함 범위, 통화, 유효일, 원본 메시지 출처를 한 견적 단위로 기록한다. 답변 없는 금액은 null/미확인이다.
3. 후보 ID → 견적 ID → 원본 출처가 명시적으로 연결되는 저장/조회 계약을 별도 승인한다. 메시지 전송 또는 발주 기능은 이 범위에 포함하지 않는다.
4. $3,000 출시비와 API 사용량은 별도 설정/검증 항목으로 다룬다. DDP·샘플·광고·예비비를 포함한 계산이 없으면 FINAL GO를 부여하지 않는다.

새 스키마·데이터 이관·후보 생성은 수행하지 않았다. 이 문서는 저장 위치와 누락된 연결을 확인하고 다음 최소 범위를 제안하는 기록이다.
